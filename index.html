Pipeline

From product data to evaluation

The workflow is designed around schema-guided extraction and repeatable comparisons across model sizes and adaptation strategies.

01 / INPUT

Instruction + source + schema

Each example provides the extraction instruction, source product content, and a target JSON schema.

02 / ADAPT

Fine-tune Qwen2.5

Compare LoRA FP16 with QLoRA 4-bit and 8-bit configurations across 0.5B, 1.5B, and 3B models.

03 / GENERATE

Produce structured JSON

Run deterministic generation and parse predictions into JSON objects for downstream evaluation.

04 / EVALUATE

Measure output quality

Report JSON parse success, schema compliance, exact match, field accuracy, and generation failures.

Metric guide

How to read the scores

JSON parse success

Share of generated outputs that the evaluation parser accepts as JSON.

Schema compliance

Share of outputs passing the configured schema validation. Check each run's validation denominator.

Exact match

Share of predictions whose parsed JSON structure equals the expected JSON object.

Field accuracy

Correct expected leaf fields divided by evaluated expected fields; this can remain high even when full-object exact match is lower.

Interpretation: A high JSON parse rate indicates syntactic reliability, not necessarily correct extraction. Exact match is stricter than field accuracy because one incorrect or missing value can make an entire object fail exact match.
